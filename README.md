## Алгоритм приоритета очереди

### Два независимых потока

1. **Общий пул** — предзапись (`appointment`) и QR-талоны (`qr`).
2. **Живая очередь** (`live`) — не участвует в общем пуле, вызывается оператором отдельно.

### Веса в общем пуле

| Источник | Вес |
|----------|-----|
| `appointment` (предзапись) | 100 |
| `qr` (QR-талон) | 60 |

### Правила ( НАДО ПРОДУМАТЬ!!! ) пока что это:

- **FIFO внутри одного приоритета** — при равном весе раньше вызывается тот, кто раньше создан.
- **Активация предзаписи** — талон становится доступен для вызова за **10 минут** до `scheduled_at`.
- **Опоздавшая предзапись** — если клиент опоздал больше чем на **15 минут**, его вес понижается до уровня `qr` (60).
- **Anti-starvation** — если любой талон ждёт больше **45 минут**, его вес поднимается до **200** и он обгоняет всех. Гарантия ограничения времени ожидания.

### Защита от двойного вызова

При вызове следующего клиента используется конструкция SQL:

```sql
SELECT ... FROM tickets
WHERE status IN ('waiting', 'scheduled')
FOR UPDATE SKIP LOCKED;
```

`FOR UPDATE SKIP LOCKED` гарантирует, что **два окна одновременно не получат один и тот же талон**. Если строка уже заблокирована другим окном — она пропускается, окно берёт следующую.

## Пользовательские сценарии

### Клиент

- Выбирает отделение и услугу.
- Записывается на дату и время, получает электронный талон.
- Присоединяется к очереди по QR-коду в отделении.
- Видит статус талона, ожидаемое время обслуживания и номер окна после вызова.
- Отменяет запись.

### Оператор

- Открывает и закрывает окно.
- Добавляет клиента из живой очереди.
- Вызывает следующего клиента и завершает обслуживание.
- Возвращает клиента в очередь.
- Видит источник талона: предзапись, QR, живая очередь.

### Руководитель отделения

- Настраивает правила приоритета.
- Видит очередь в реальном времени.
- Контролирует среднее и максимальное время ожидания.
- Видит загрузку окон и число обслуженных клиентов.
- Получает список отклонений и незавершённых талонов.

## Журнал событий ( ПОКА ЧТО ТОЖЕ СЫРОЙ ) (МОЖЕТ БУДЕТ ВОВСЕ ВЫБРОШЕН )

Все изменения талонов фиксируются в таблице `ticket_logs`:

- `created` — талон создан.
- `call` — вызван к окну.
- `complete` — обслуживание завершено.
- `cancel` — отменён.
- `return_to_queue` — возвращён в очередь.

Каждое событие содержит: `ticket_id`, `event_type`, `comment`, `timestamp`.
